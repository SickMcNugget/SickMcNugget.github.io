I've been plagued by questions concerning the function of CPUs recently. I have a rough idea of how a CPU functions, but I'm more interested in the nitty-gritty than some high-level overview. When I'm running code, what happens? I'm not just asking about the generated assembly, I'm asking about how this relates to the physical attributes of a CPU. I want to be able to reason about the size of my L1, L2 and L3 caches when I'm writing code. I want to write code that easily converts into [Single Instruction/Multiple Data][SIMD] (SIMD) instructions where possible. I want to know how different CPU units work, such as the [Memory Management Unit][MMU] (MMU), [Input/Output MMU][IOMMU] (IOMMU), [Floating Point Unit][FPU] (FPU), [Arithmetic Logic Unit][ALU] (ALU) and whatever else there may be. I want to understand instruction set extensions, such as AVX2 and AVX512. I want to understand the overhead of a context switch, and what a no-op really is. I want to understand how many instructions per cycle I should expect a line of code to be capable of. I want to better understand the interchange between the CPU frontend and the CPU backend. Finally, I want to be able to refer back to this page and remind myself of what I have learned.

# The list
Below is a list of Webpages with short descriptions of how they are helpful and what they show.
- <https://uops.info/table.html> - Microcode Instruction explorer. Allows you to determine the throughput of a CPU instructions.
- <https://godbolt.org/> - Compiler explorer. Allows you to see the generated assembly for a code snippet.
- <https://cpu.land/> - A high-level explanation of what CPUs do
- [WikiChip][WikiChip] - A website designed specifically to show hardware architectures. Contains block diagrams of CPUs and a rundown of all their features. An amazing site, but it seems to be unreachable without web archive.
- <https://chipsandcheese.com/p/popping-the-hood-on-golden-cove> - An investigation into Intel's Alder Lake launch
